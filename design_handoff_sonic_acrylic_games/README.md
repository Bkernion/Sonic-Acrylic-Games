# Handoff: Sonic Acrylic Games — Daily mobile game app for a musical-artist brand

## Overview

Sonic Acrylic Games is a daily-puzzles mobile app (iOS + Android), positioned for fans of rock / indie / singer-songwriter music. Each day a small lineup of artists (drawn from a curated pool of ~150) is announced, and six word-and-music puzzles are generated by an automated content pipeline. Players build streaks, compete on leaderboards, and listen to the founder's music in the background via a persistent NowPlaying ribbon. The brand voice is editorial, literary, and musician-auteur — the puzzles are framed less as a "game app" and more as a daily zine.

## About the Design Files

The files in this bundle are **design references created in HTML/JSX as prototypes**. They show intended look, layout, copy, type, and color — they are **not production code to copy line-for-line**.

The implementation task is to **recreate these screens in the target codebase's environment** — typically a React Native / Expo or native (SwiftUI / Jetpack Compose) app — using its established patterns. If no codebase exists yet, **React Native + Expo** is recommended for cross-platform shipping; otherwise pick the framework that matches the team's strengths.

The HTML prototypes use React 18 + Babel inline transforms with global-scope components (no bundler). Treat the JSX as **structured design specs**, not modules to import.

## Fidelity

**Mid-fidelity.** Colors, type, spacing, and copy are final and intentional — recreate them precisely. Layouts are pixel-precise on a 380×800 viewport (a smaller-than-iPhone working size). Real device targets will be larger; scale the spacing scale proportionally and let the typography breathe. Photography is shown as duotone striped placeholders — final implementation will need real artist imagery (sourced separately).

Interactions are described but not built out — no real drag-drop, no real keyboard input, no real network. Implementer should wire up real interactions following the behavior notes below.

## Screens / Views

There are **8 screens**, each shown in the prototypes inside both an iOS and Android device frame. The brand chrome (AppBar, NowPlaying ribbon) is the **same on both platforms** — platform differences come only from the OS chrome itself (status bar, nav bar, home indicator).

### 02 · Connections (Marginalia)
**Purpose** · NYT-Connections-style puzzle. Sort 16 song titles into 4 hidden groups of 4.

**Layout**:
- AppBar: `CONNECTIONS · 1 OF 6`
- Serif prompt (19px, 500): "Sixteen songs. / Four hidden categories." + italic taupe subtitle hint
- "MISTAKES LEFT" mono label + 4 dots (filled = remaining)
- 4×4 grid of square tiles, aspect-ratio 1, gap 6px, serif type 10px centered. Selected tiles = solid ink black bg with paper text.
- Marginalia note (rust 2px left border, paper-2 bg, italic serif quote — "soft hint from the curator")
- Action row: SHUFFLE (ghost), CLEAR (ghost), SUBMIT (rust filled, flex 1.4)

### 03 · Spell (Five Letters / Wordle)
**Purpose** · Five-letter word guess in 6 tries. The word is something the day's lineup "keeps reaching for."

**Layout**:
- AppBar: `SPELL · 3/6`
- Italic taupe prompt (13px)
- 6×5 grid of 46×46 tiles, gap 5px, serif 22px. States:
  - hit (right letter, right slot) = rust bg, paper text
  - near (right letter, wrong slot) = taupe-2 bg, paper text
  - miss = hair bg, taupe text
  - empty = paper bg with hair-2 border
- 3-row keyboard at bottom: QWERTY layout, mono labels, keys 26px wide × 38px tall (↵ and ⌫ are 36px+). Key tinting matches tile state once that letter has been used.

### 04 · Lyric (Fill the Gap)
**Purpose** · One missing word in a famous lyric. Multiple-choice (4 options), one try.

**Layout**:
- AppBar: `LYRIC · ONE TRY`

- Serif lyric (22px, 500), with the gap as a rust-underlined `____` placeholder, italic
- Italic taupe "decoy" caption (13px, left-bordered)
- 4 choice tiles vertically, each: serif word (17px) + mono A/B/C/D label right
- COMMIT button (rust filled, full-width)
- NowPlaying mini-pill

### 05 · Chronology (Order)
**Purpose** · Drag 5 records onto a year rail in the order they were released.

**Layout**:
- AppBar: `CHRONOLOGY · 5 RECORDS`
- Italic taupe prompt
- Two-column body:
  - Left rail (54px): vertical ink line with year stops + dots (filled rust = placed, hollow paper = empty drop target)
  - Right body: stack of 7 row slots (56px each). Cards drawn 4 states:
    - Placed: paper-2 bg, hair-2 border, serif title + mono LP-year label
    - Drop zone: dashed rust border, transparent, label "— drag here —"

- "↓ two left in the tray ↓" italic helper
- NowPlaying mini

### 06 · Attribute (Quote match)

**Layout**:

### 07 · Influence (Web)
**Purpose** · Draw lines between two columns of 5 artists, matching teacher → pupil.

**Layout**:
- AppBar: `INFLUENCE · 3/5 DRAWN`
- Italic taupe prompt
- Web region (360px tall):
  - "TEACHER" / "PUPIL" mono labels centered above each column (positioned at 32% / 68% horizontally)
  - 5 dot rows, evenly spaced. Left dots = ink solid; right dots = rust (matched) or paper-hollow with ink ring (unmatched).
  - Names sit outside the dots: teacher names right-aligned at 32% minus 12px; pupil names left-aligned at 68% plus 12px.
  - SVG bezier threads connect dots: solid rust 2px (matched), taupe 1.5px dashed (hover/hint).
  - **Implementation note**: in the prototype, SVG and HTML use a shared % coordinate space (viewBox 0 0 100 360, preserveAspectRatio="none", non-scaling-stroke) so threads align with dot centers regardless of container width. Real impl should keep that invariant.

## Interactions & Behavior

### Daily content pipeline
- A curated artist list of ~150 names lives server-side.
- Each day, a deterministic seed picks **5 artists** as that day's lineup.
- For each of the 6 games, an automated agent generates the day's puzzle by finding overlaps among the 5 artists' catalogs (songs, lyrics, quotes, discography years, influences).
- Results are precomputed and cached for the whole user base — every player gets the same puzzle each day (this is what enables leaderboards).
- Reveal at 00:00 local time. Carry-over UI for in-progress puzzles.

### Streak & leaderboard
- Streak persists across days; broken if a day is missed without finishing the connections puzzle (the "anchor" game). Other games are optional.
- Leaderboard is per-day, per-game. Show user's rank "#X / N" on home Side B.
- Friend leaderboards (long-term) — not in this mid-fi.

### NowPlaying
- A queue of the artist's own music plays in background while in-app. Persistent — does not stop between screens.
- Play/pause controls in the ribbon. Full variant shows scrub state implicitly via the equalizer animation.
- Mini variant on game surfaces saves space; expand to full on tap.

### Game-specific behavior
- **Connections**: tap to select, max 4 tiles, submit reveals match or +1 mistake. Auto-shuffle after each correct group. 4 mistakes = game over.
- **Spell**: virtual keyboard, 6 guesses. After commit, tiles flip-reveal state. Keyboard tints update.
- **Lyric**: one-tap commit. No re-tries.
- **Chronology**: drag from tray to year slot. Submit reveals correct / nudge incorrect cards into place.
- **Attribute**: tap to select, then SUBMIT GUESS commits.
- **Influence**: draw connections by tap-from-left-to-right (or drag a thread). Two columns of 5, exactly 5 lines to draw. Some lines visibly easier than others — design supports "hover preview" via dashed taupe thread.

### Tip Jar
- Surfacing on home Side B and on every win screen.
- Tap → modal with preset amounts ($2 / $5 / $10 / custom). Tied to the artist's existing payments (Stripe, Apple Pay, etc.).

### Sharing (win screen)
- Tap SHARE → system share sheet with a pre-rendered card. (The prototype's old "share grid" was replaced with a streak-visualizer surface — implement share as a generated PNG separately, e.g., via Canvas or server-rendered.)

## State Management

Minimum daily state per user:
- `dailyEditionId` (date string)
- `lineupArtists: string[5]`
- `gameProgress: { [gameId]: { startedAt, completedAt, mistakes, guesses, result } }`
- `streak: { current: number, longest: number, lastCompletedDate: string }`
- `leaderboardRank: { [gameId]: { rank, total } }`
- `musicPlayer: { trackId, isPlaying, position }`

Suggested architecture:
- Daily content: fetched once on app open, cached locally for the day.
- Game state: local-first (offline-friendly), synced to backend on completion.
- Music: persistent service (React Native track-player on RN; AVAudioPlayer on iOS native; Media3 on Android native).

## Implementation order (suggested)

1. **Tokens** — port the editorial palette + type scale into the codebase's theming system.
2. **Brand chrome** — AppBar, Streak chip, NowPlaying ribbon. Get these right first; they appear on every screen.
3. **Home** — easiest to validate the design system in production.
4. **Connections** — most complex interaction; build the tile-selection state machine.
5. **Spell / Lyric / Attribute** — simpler turn-based games, similar pattern.
6. **Chronology / Influence** — drag + line-drawing UIs, save for last.
7. **Win screen** — the streak visualizer is the focal element; everything else is structure.
